# Fork test builds are pre-release GitHub Releases from hyphenated tags

This fork (`frozenss/Genshin-Subtitles`) is a contribution workspace toward upstream `qew21/Genshin-Subtitles`, not an independent distribution — yet test binaries must be downloadable by users who are not logged in to GitHub. That requirement forces the channel: Actions artifacts require a GitHub login even on public repos, and draft releases are visible only to repo writers, so a published GitHub Release marked **pre-release** is the only native option. The mechanism already lives in `release.yml`: a tag containing `-` publishes with `prerelease: true` and skips the website deploy. Decision: test builds are tagged `<AssemblyVersion>-fork.N` (e.g. `1.6.12-fork.1`) as annotated tags whose message — becoming the release body — opens with "fork test build, not an official release". The suffix is `-fork.N`, never `-pre` (upstream's own prerelease vocabulary, e.g. `1.6.13-pre`), and `AssemblyVersion` is deliberately **not** bumped ahead of upstream: the in-app updater reads upstream's stable manifest from `2langs.com`, so staying at-or-behind upstream's number lets it shepherd test users back to the official build once upstream publishes a higher version. The `deploy-website` job is additionally gated on `github.repository == 'qew21/Genshin-Subtitles'` so a bare tag pushed to the fork by accident can fail visibly in the release job but never reach the deploy (forks hold no `DEPLOY_*` secrets, and the stable manifest belongs to upstream's site). Runbook: `docs/agents/test-build-releases.md`.

**Considered Options**: Actions artifacts (CI-native, but anonymous users cannot download them — a hard fail for the stated audience); draft release (invisible to anyone without write access, so anonymous sharing is impossible); nightly.link (anonymous artifact downloads via a third-party proxy — an external dependency whose links rot); bumping `AssemblyVersion` ahead of upstream (distinguishes the bits, but the updater would then see test users at-or-above upstream's version and never offer the migration back to official builds).

**Consequences**: the fork carries Releases despite being a contribution workspace — the pre-release badge plus the `-fork.N` tag is what keeps them from reading as official versions, and pre-releases never claim the "Latest" badge; test releases are kept after upstream merges the corresponding PR (links stay valid, provenance stays traceable) rather than cleaned up; stable numbering, the website download, and the update channel remain upstream-only forever.
